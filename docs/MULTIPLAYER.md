# 十五款遊戲好友 PK：手動設定與驗收

目前 `assets/supabase-config.js` 留空。十五場單人練習、島圖、球迷造型、合影／PNG、模擬賽事與政策挑戰均可離線使用。好友開房／加入保持停用，不發出網路請求，不產生假房間、假玩家或假成績。「鬥牛猜招」單人模式的對手明確標示為電腦。

新版每種遊戲第一次就緒前，可先做最多 12 秒不計分操作試玩或跳過；離開試玩不送出 ready，結束後才送出本人就緒。正式局仍由伺服器決定共同時間／種子，試玩結果永不提交。這個前端流程已用 Node 後端形狀替身測試，仍待實際兩台裝置驗證。本版沒有資料表改動，也未執行任何 SQL；沿用下述原始＋增量腳本。模擬路人與房間統計完全分開。

## 由你手動設定（本次沒有執行）

1. 在自己的 Supabase 專案啟用 Authentication → Anonymous Sign-ins。
2. 新專案先手動套用 `supabase/schema.sql`，再套用 `supabase/games-v2.sql`。已有原版資料庫只需新增套用 `games-v2.sql`。先備份自己的資料；增量保留房間／成員，將舊投籃結果轉為結構化結果。舊進行中／已完成房間維持投籃；等待中新房間採場地遊戲，再開一局時切換為該場專屬玩法。
3. 在 `assets/supabase-config.js` 填入公開 Project URL 與 publishable／anon key，不能放入 service_role、sb_secret_ 或資料庫密碼。此次未修改該設定。
4. 重新開啟前端。只有 Auth、v2 能力檢查及真實房間摘要都成功才啟用好友入口；尚未升級後端會提示套用增量 SQL。
5. 兩台裝置必須讀取相同新版靜態前端；本機 file 連結無法分享硬碟。可由你之後手動更新 Pages 或提供同網路的靜態網站。本次未 push／部署。

原生 fetch 呼叫 Auth／PostgREST RPC，每兩秒同步，不需 SDK、CDN 或另開 Realtime publication。

## 每局的共同條件

- `court_id` 決定唯一 `game_id`。15 個球場各可同時開多間房，房間最多兩位真人。
- 伺服器保存局數 `round`、共同種子 `game_seed`、共同 `starts_at`／`ends_at`。雙方就緒後由房主開始，先倒數五秒。
- 題目依種子與題號決定；風向、障礙、空檔、跑位及假動作不取決於玩家送出次數。節奏是固定 0.6 秒，兩邊從共同開始時間起算。
- 各場規則與上限見 [README 遊戲表](../README.md)。時間上限依遊戲不同，非全部 30 秒。競速、記憶、計步及全能賽各用自己的結算規則，相同結果平手。
- `nba_submit_result` 接收本人結構化結果，以及 room／round／game／seed。資料庫檢查成員、局數、共同種子、數值範圍、結果關係與時間；不接受對手 user_id。只可提交一次。
- 先完成的遊戲可先交結果，其他遊戲到時自動結算。一般結果最晚在上限後 15 秒送到；一方未交時已交者判勝並標示缺交，雙方都未交則不計勝負。重送限尚未成功且未截止時使用。
- 房主重開會增加局數、換新種子並清空結果／就緒，上一局遲到的結果會被拒絕。前端也忽略舊局的過期快照。
- 換場會停止該遊戲的畫面計時及操作；若仍在真人對局，伺服器時間繼續。回原場會恢復當頁的進度；重新整理會失去尚未提交的本機操作，請完成一局後再整理。
- 同一房主最多五個活躍房間，兩小時到期。等待中第二人離開可讓出空位；房主離開或對戰中離開會取消房間。

## 鬥牛猜招：封存雙方選擇

共 10 回合、各 7 秒。房主先攻，雙方交替攻守，各攻五次。進攻切左／切右／跳投；防守選對應防法。進攻未被猜中得兩分。

`nba_duel_moves` 啟用 RLS，對 public／anon／authenticated 均沒有直接 SELECT 或寫入授權。`nba_choose_move` 只寫入 auth.uid() 的本回合招式，在房間鎖下檢查兩人身分、局數、遊戲、回合與是否已鎖定。另一位玩家無法提前讀取已交招式；客戶端只收到「自己已送出」布林值。

雙方都送出，或該回合截止後，`nba_get_room` 才回傳該回合的攻守選擇與得分。截止後不能再補舊回合；進攻逾時無分、防守逾時且進攻已出招則攻方得兩分。70 秒結束由後端直接產生雙方結果，禁止客戶端替此遊戲提交分數。

## 權限與結算

沿用原房間／成員的 RLS、`(room_id,user_id)` 主鍵與 `(room_id,slot)` 唯一限制。加入前先 FOR UPDATE 鎖房，再檢查重複加入、球場與兩人上限。沒有資料表直接 INSERT／UPDATE／DELETE 權限。

結果由 `nba_compare_result` 比較：計分比高、繞樁比含罰秒時間低、五點／接力比完成與時間或進度、記憶比最長路線／輪數、禁區比關卡／成功步數、全能賽逐項 1／0.5 場勝分。前端有相同規則供離線測試。一般成績仍是客戶端遊戲結果與資料庫範圍驗證，未實作伺服器逐步重播；猜招則全由後端選擇紀錄計分。

## 兩台裝置驗收（全部尚待實際連線）

1. A、B 使用獨立匿名身分開啟相同新版網站，確認已連線。一般瀏覽器的兩個分頁可能共享身分，請用兩台裝置或獨立瀏覽器環境。
2. A 選潮汐一號、填暱稱開房、分享完整連結。B 開連結後應定位相同球場與遊戲，填暱稱加入。兩邊應看見同兩位真人。
3. A 再加入必須顯示已加入，第三個獨立身分 C 同時嘗試也只能顯示已滿；另一球場輸入該碼必須拒絕。驗證同球場不同房間互不干擾。
4. 一人就緒不能開始；兩人就緒後由 A 開始。核對 round、game_id、game_seed、starts_at 一致；比較兩邊障礙／風力／題目，手機與鍵盤均可操作。
5. 先測投籃不同分數與雙方不出手平手；再測榕樹繞樁不同罰秒、霓虹節奏不同連擊，以及兩邊同樣結果的平手。
6. 中央草地：A 先選招，B 尚未選時不能看見 A 招式，包括 RPC 回應與直接資料表讀取。B 選後雙方才揭曉；同回合重送應拒絕。換攻守、故意逾時，70 秒後核對雙方比分與各攻五次。
7. 依 README 的十五場表逐一測其餘遊戲；重點核對五點／接力用時、記憶同長比輪數、禁區同關數比步數、全能賽三項場勝分及平手各 0.5。
8. 房主再開一局：round +1、新種子、雙方未就緒。用舊 round、錯 game_id 或 seed 重送結果要拒絕；同一結果重送也不能覆寫。B 不能代替 A 開始／重開。
9. 嘗試直接 PATCH 自己／對方成績與讀取 nba_duel_moves，應被權限拒絕；新 RPC 沒有對手 ID 參數。檢查第三人沒有任何入房／交招／交成績權限。
10. 測中斷連線、重送、傳輸寬限、時間截止、離場及重回原場；不能出現替代玩家或假成績。
